1. Buddy Android (ghorbelhamdi/buddy-android) — Local 127.0.0.1 Loopback Stack

Buddy runs both the CLI agent runtime and the Android Accessibility MCP bridge directly inside the handset on Android 11+ (64-bit) with zero ADB, zero root, and zero PC. [1] (https://github.com/ghorbelhamdi/buddy-android)
• On-Device Execution Loop.
	• Android Accessibility & Overlay Service. Exposes UI inspection (read screen), coordinate/node tapping (tap), text injection (type), scrolling, notification rules, media/calendar hooks, and a background headless browser.
	• Embedded proot Alpine Linux Sandbox. Runs inside the app container itself, hosting full CLI agents (Claude Code, Codex, OpenCode, Google Antigravity CLI, and Grok Build) locally on the device.
	• Local 127.0.0.1 MCP Bridge (mcp-bridge). Connects the CLI agents running inside the proot sandbox directly to the Android Accessibility service over loopback (127.0.0.1) and standard stdio so the CLI agent drives the phone UI in real time without leaving the device.
	• On-Device APK Compiler & Installer. When Linux tools are enabled inside Buddy, the agent can write code, compile a new Android APK directly inside the phone's proot environment, and trigger Android's package installer to deploy it on the spot.
	• Action Guardrails. Pauses for explicit user confirmation before executing high-impact actions (sending messages, posting, purchasing, or deleting). [1] (https://github.com/ghorbelhamdi/buddy-android), [2] (https://appteka.store/app/bd0r335100)

2. XNet-NGO On-Device Stack (aiope + droid-gguf + neural-route)

The XNet-NGO GitHub Organization splits on-device Android execution and local model inference into modular Kotlin and Go repositories: [1] (https://github.com/XNet-NGO)
• Local GGUF Engine (XNet-NGO/droid-gguf & XNet-NGO/inf-serv).
	• droid-gguf. A native Kotlin GGUF inference engine for Android exposing an OpenAI-compatible /v1/chat/completions API directly on localhost.
	• inf-serv. A lightweight Kotlin HTTP Server-Sent Events (SSE) inference server streaming tokens locally on Android.
	• llm-core & neural-route. Kotlin core libraries handling local model execution and neural request routing across local vs. external endpoints. [1] (https://github.com/XNet-NGO)
• 73-Tool Agent Runtime (XNet-NGO/aiope).
	• Autonomous 140-Round Loop. Runs up to 140 chained tool calls per task across 73 built-in tools (browser automation, SSH client, run_sh + run_proot Alpine Linux shell, and MCP tool servers).
	• Local ONNX Vision & Vector RAG (XNet-NGO/deps & small-rag). Runs Bekko ONNX embeddings, RT-DETR ONNX object detection, facial presence detection, and SQLite cosine-vector RAG over local PDFs 100% offline with zero telemetry and zero Google Play Services. [1] (https://github.com/XNet-NGO/aiope), [2] (https://github.com/XNet-NGO)
• Multi-Node & Network Mesh (aiope-headless & mcp-netbird).
	• aiope-headless. A headless Go daemon for running the AIOPE agent runtime in background or server environments.
	• mcp-netbird. A Go MCP server managing encrypted peer-to-peer mesh networking (NetBird) across devices without exposing public ports. [1] (https://github.com/XNet-NGO)
